# Day 24 — AWS Hybrid Cloud Site-to-Site VPN Architecture

## Overview

This project demonstrates a hybrid-cloud architecture where an AWS VPC communicates with a simulated on-premises network through an AWS Site-to-Site VPN.

The on-premises environment is simulated using a separate AWS VPC containing an Ubuntu EC2 instance running StrongSwan.

## Virtual Private Gateway

The Virtual Private Gateway provides the AWS-side termination point for the Site-to-Site VPN.

It is attached to:

```text
Hybrid-VPC
```

---

## Customer Gateway

The Customer Gateway represents the simulated on-premises VPN endpoint.

It points to the public address of:

```text
On-Prem-VPN-Router
```

The router runs StrongSwan and terminates the VPN tunnel.

## Simulated On-Premises Environment

The simulated on-premises network uses:

```text
192.168.1.0/24
```

The Ubuntu VPN router has:

```text
192.168.1.209
```

The router performs the role that would normally be handled by an on-premises VPN appliance.

---

## StrongSwan

StrongSwan provides the IPsec VPN functionality on the Ubuntu router.

The VPN configuration was based on the configuration generated by AWS for the Site-to-Site VPN.

The project used:

* IKEv1
* Pre-shared-key authentication
* AES encryption
* SHA-1 integrity
* Diffie-Hellman Group 2
* IPsec ESP
* VTI-based routing

Actual VPN secrets are intentionally excluded from this repository.

## Routing Flow

Traffic from the simulated on-premises network to AWS follows this path:

```text
192.168.1.209
      │
      ▼
Ubuntu VPN Router
      │
      ▼
StrongSwan / IPsec
      │
      ▼
VTI Tunnel1
      │
      ▼
AWS Virtual Private Gateway
      │
      ▼
AWS Private Subnet
      │
      ▼
10.0.2.183
```

The reverse path is intended to follow:

```text
10.0.2.183
      │
      ▼
AWS Route Table
      │
      ▼
Virtual Private Gateway
      │
      ▼
Site-to-Site VPN
      │
      ▼
StrongSwan
      │
      ▼
192.168.1.209
```

## Linux Policy Routing

The Linux VPN router uses policy routing to ensure AWS-bound traffic is sent through the VTI.

The important routing rule is:

```text
100: from all to 10.0.0.0/16 lookup 220
```

The route in table 220 points AWS traffic through:

```text
Tunnel1
```

The routing decision was verified with:

```bash
ip route get 10.0.2.183
```

The successful result was:

```text
10.0.2.183 dev Tunnel1 table 220 src 192.168.1.209
```

## Connectivity Verification

The final test was performed from the simulated on-premises router:

```bash
ping -c 4 10.0.2.183
```

Result:

```text
4 packets transmitted
4 packets received
0% packet loss
```

This demonstrated successful network connectivity across the Site-to-Site VPN.

## Important Architecture Note

This project simulates an on-premises network using AWS infrastructure.

A production architecture would normally look like:

```text
Corporate Network
      │
      ▼
Physical/Virtual VPN Appliance
      │
      │ Internet
      ▼
AWS Site-to-Site VPN
      │
      ▼
Virtual Private Gateway / Transit Gateway
      │
      ▼
AWS VPC
```

The laboratory version replaces the physical/virtual corporate VPN appliance with an Ubuntu EC2 instance running StrongSwan.

This allows the core VPN, routing, encryption, and troubleshooting concepts to be practiced without requiring physical networking equipment.
